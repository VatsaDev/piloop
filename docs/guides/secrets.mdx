---
title: Secrets
description: Give agents the API keys that MCP servers and model gateways need, without a key in any file.
---

`piloop secret set` stores a key. Each agent that starts after it gets the key in its environment.

```bash
printf %s "$EXA_API_KEY" | piloop secret set EXA_API_KEY
```

On a terminal, `piloop secret set EXA_API_KEY` asks for the value and does not show it. The name of a secret is the
environment variable that agents get it in. `piloop secret list` shows the names, never a value:

```text
  name          of     set                by
 ───────────────────────────────────────────────
  EXA_API_KEY   home   2026-10-25 03:22   human
```

`piloop secret rm EXA_API_KEY` deletes it.

## Who gets a secret

- A secret is the home's, for every campaign. With `--campaign`, it is one campaign's, and it wins over the home's
  secret of the same name.
- An agent gets only the secrets that its job names: the variables of its role's [MCP servers](/guides/mcp-servers),
  and the secrets in its harness's `env`.
- A [worker on another machine](/guides/remote-workers) gets the values from the server when it starts the job.
- An agent can set the secrets of its own campaign, and not those of the home.

<Warning>
  An agent can read the keys in its environment. The database of the home holds the values in plain text: `piloop sql`
  cannot read them, but a copy of the database file can.
</Warning>

## Model access

`[harness.<name>] env` gives the agents of a harness more variables, each a value or a secret. To send Claude Code
through a model gateway:

```toml
[harness.claude.env]
ANTHROPIC_BASE_URL = "https://gw.example.com"
ANTHROPIC_API_KEY = { secret = "ANTHROPIC_API_KEY" }
```

The table changes only `env`, and the other keys of the built-in harness stay. Without `env`, an agent uses the login
of the machine that runs it.

## PILOOP_SECRETS_COMMAND

`PILOOP_SECRETS_COMMAND` is deprecated, and piloop 0.5.0 removes it. Until then, a secret that `piloop secret list`
does not show comes from the environment of the machine that runs the agent, and `piloop doctor` names it. To move the
keys that the command prints:

```bash
sh -c "$PILOOP_SECRETS_COMMAND" | while IFS='=' read -r name value; do
  printf %s "$value" | piloop secret set "$name"
done
```

Then unset `PILOOP_SECRETS_COMMAND`, and write the service unit again.
