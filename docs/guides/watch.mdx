title: Watching a campaign
description: piloop watch shows the campaign on one screen, with keys to act on it.
---

`piloop watch` is a terminal app over the database. It shows every campaign, or one campaign with
`piloop watch <campaign>`. It reads the database again whenever the daemon or an agent writes to it.

## The screens

The first screen lists every campaign, the active ones first. Press `enter` to open one, and `esc` to come back.

It shows one row per campaign: its status, the head and its gain over the baseline, the live agents, the ready ideas, the
inbox, the tokens and the last event.

A campaign has a header, four panels on the left, and the main pane on the right, which shows the selected row in
full:

The header shows the head, the number of keeps and the tokens. The second line shows the progress against `[stop]`,
and the spend against `[spend]` when the campaign has a budget. Its run count (`run 7/10`) counts the runs as
`max_runs` does. With several [tracks](/concepts/tracks), one more line
shows each track.

## Panels and keys

These keys work on the screen of a campaign. `?` and `q` also work on the list of campaigns.

| Key | Action |
|---|---|
| `1` to `4`, `tab` | Move between the panels. |
| `0` | Move into the main pane, to scroll it. |
| `↑` `↓`, `j` `k` | Select a row. |
| `/` | Filter the panel. `enter` applies the filter, `esc` clears it. |
| `?` | List the keys of the panel. |
| `esc` | Go back to the list of campaigns. |
| `q` | Quit. |

| Panel | Rows | Main pane | Keys |
|---|---|---|---|
| [1] Inbox | The unacknowledged items, most urgent first, without the items that you wrote. | The item and its thread. | `a` acknowledge, `A` acknowledge every item shown, `r` reply |
| [2] Agents | The running agents: `●` working, `○` idle, `◐` waiting on a dialog. | The agent, its task, and its last 60 lines of output. | `enter` bring it to the front, `s` steer |
| [3] Ideas | Seeds, then proposed, ready, scheduled and parked ideas, and by priority within each status. | Hypothesis, plan, links, runs and comments. | `y` approve, `p` park, `x` reject, `+` `-` priority |
| [4] Candidates | The candidates, newest first, then the imported references. The title shows the head after each keep as a sparkline. | Verdict and reason, metrics against the parent, summary. | none |

## What the keys write

Each key writes as `PILOOP_ACTOR`, which is `human` unless you set it. The `events` table records the write like any
other.

- **Acknowledge** does what `piloop inbox ack` does.
- **Reply** asks for the text and a priority (default 2). It writes a `decision` comment that replies to the first
  item of the thread. The orchestrator's next wait returns with it, and the orchestrator acknowledges it after it
  applies it.
- **Bring to the front** does what the [runtime](/concepts/runtimes) of the agent defines, for example it focuses the
  agent's tab. When the runtime has no view of its own, a notification says where to look instead.
- **Steer** queues text for the agent's next turn, as `piloop prompt` does. A runtime can refuse it, for example while
  the agent waits on a dialog. A notification says why.
- **Approve, park and reject** ask why. Each one writes the status change and a `note` on the idea with the reason.
  A seed cannot be approved: research develops it into an idea first (`piloop idea develop`).

## In Herdr

By default, the agents run as background processes. To see every agent in a terminal pane, install
[Herdr](https://herdr.dev) and set `runtime = "herdr"` in `piloop.toml`. Then piloop has its own Herdr session,
`piloop`, with one workspace for each campaign. The first tab of a workspace is `home`: a shell on the left and
`piloop watch <campaign>` on the right. Each agent gets its own tab, named after its role, its id and its idea:

```text
my-campaign
  home                                shell │ piloop watch
  implementer-12 idea#5 Stacking with a meta-learner…
  research-7
  watchdog-13
```

`piloop attach <agent-session-id>` opens an agent's tab from any terminal.
