A campaign costs money in two ways: the tokens that the agents use, and what the campaign pays outside piloop, such as
GPU time or paid APIs. piloop measures the first and enforces a limit on both.

## Tokens

When an agent ends, piloop reads the tokens that it used from the harness's own session file. This works for Claude
Code, Codex and pi, and does not need Entire. piloop writes the totals to `workers.usage`:

```json
{"input": 120345, "output": 18230, "cache_read": 950112, "cache_write": 40211, "total": 1128898, "turns": 41, "source": "…"}
```

- `piloop status` and `piloop watch` show the tokens of each campaign.
- The kept lineage shows the tokens that each candidate cost.
- `[stop] max_tokens` ends the campaign when the agents of the campaign have used that many tokens in total.

```toml
[stop]
max_tokens = 50_000_000
```

For every harness, `input` is the input that the prompt cache did not serve, and `cache_read` and `cache_write` are
the cached input. `total` is the harness's own count of the session's tokens.

## Stop conditions

The `[stop]` table ends the campaign when one of its conditions holds:

<Stop />

When a condition holds, the campaign becomes `stopped`. The daemon tells the running workers to commit and stop, and
ends them 10 minutes later. It scores what they committed. It drops the queued runs and the requested agents. Then
the `stopped` triggers fire once: by default, the watchdog's closing review, which writes the closing report. The
triggers request nothing more, but an agent that you request with `piloop launch` still starts. Without a `[stop]` table, the campaign has no end.

`piloop campaign stop <campaign>` stops a campaign by hand, the same way. With `--kill`, the workers are ended at once.
`piloop stop` stops the daemon, not the campaign.

To resume a stopped campaign, change its `[stop]` table and run `piloop init`.

These limits are the built-in stop rule, `limits`. A plugin can add another stop rule. You select it with
`[plugins.stop_rule]` in `piloop.toml`. [Stop conditions](/architecture/extension-points#stop-conditions) has an
example.

## Spend outside piloop

`[spend]` is a hard limit in US dollars on what the campaign costs outside piloop. piloop knows no vendor, so you give
it a command that prints the spend so far:

```toml
[spend]
command = ["uv", "run", "scripts/spend.py"]   # prints one number: the spend so far in USD
limit = 1000                                  # nothing new starts at this spend
notices = [300, 600]                          # each one posts a note to the inbox when crossed
interval = 300                                # seconds between two runs of the command
```

The daemon runs the command every `interval` seconds, at the root of the repo, with its own environment. The command
must print one number and exit 0 within a minute. Give it its keys through the daemon's environment; see
[Secrets](/guides/secrets).

- When the spend crosses a value in `notices`, the daemon posts one note at priority 1.
- When the spend reaches `limit`, the daemon starts no agent and no evaluation for the campaign, and posts one
  escalation at priority 0. Agents and evaluations that already run finish, and their commits are scored.
- When the command fails, the daemon holds the campaign in the same way, with one escalation for each series of
  failures. An unknown spend is never read as zero.

This is a hold, not a stop: nothing is dropped. To resume, raise `limit` in `piloop.toml` and run `piloop init`.
`piloop campaign stop` still stops a held campaign on the next tick. `closing_review` in `[spend]` says what
happens to the closing review of that stop:

| `closing_review` | What the daemon does |
|---|---|
| `"run"` (default) | It starts the closing review, also past the limit or with an unknown spend. |
| `"skip"` | It starts no closing review. The stop ends at once, and the daemon posts an escalation that says so. |
| `"wait"` | It requests the closing review, and starts it when the hold ends. It goes on reading the spend until then. |

```toml
[spend]
command = ["uv", "run", "scripts/spend.py"]
limit = 1000
closing_review = "wait"
```

A paused campaign that you stop starts its closing review at once: a pause does not hold a stopped campaign.

`piloop status` shows the spend as `$412.30/$1,000.00 spend`. Tokens are not part of the spend, because piloop has no
price table. Use `[stop] max_tokens` for them.
