A **runtime** is where an agent runs. It starts the agent, watches it until it ends, steers it with messages, shows
it to you, and stops it. piloop has two built-in runtimes. A Python package can [add more](#add-a-runtime).

A project sets its runtime with the `runtime` key of `piloop.toml`. A role can set another one with its own `runtime`
key. See [Configure a role](/concepts/roles#configure-a-role).

## What a runtime does for you

Every runtime has the same contract. These commands work with every runtime. The runtime of the agent defines what
each command does:

| You run | The runtime of the agent |
|---|---|
| `piloop prompt <worker-id> "<text>"`, or `s` in `piloop watch` | Queues the message for the agent's next turn. It never cuts the turn in progress short. |
| `piloop attach <worker-id>` | Shows the agent in this terminal. |
| `enter` on an agent in `piloop watch` | Brings the agent to the front of the runtime's own view. |
| `piloop status`, `piloop watch` | Show where you can see the agent, for example its tab, when the runtime has such a place. |
| `piloop doctor` | Checks that the runtime can run agents on this machine. |

When a runtime cannot do one of these, the command says so, and tells you where to look instead. In every runtime,
the brief, log and transcript of an agent are in its log directory: `~/.piloop/runs/<run>/` for an agent that does a
run, and `~/.piloop/workers/<worker-id>/` for the sweeping roles.

## Built-in runtimes

<Runtimes />

The invocation is the argument list of a harness that the runtime starts. `headless` is a process without a terminal,
with the first prompt in its arguments. `interactive` is a session in a terminal, and the runtime types the first
prompt after the start. Some features of a harness depend on the invocation. For example, pi takes
[MCP servers](/guides/mcp-servers#what-each-harness-gets) only in its headless invocation.

## Choose a runtime

- `subprocess` is the default. It needs nothing more than the harnesses. `piloop watch` shows the output of each
  agent. Use it for a campaign that runs without you.
- `herdr` gives each agent a terminal pane. You can read each agent, answer its dialogs and type into it. It needs
  [Herdr](https://herdr.dev). See [In Herdr](/guides/watch#in-herdr) for the session, the workspaces and the tabs that
  piloop makes.

You can mix them: for example, `runtime = "subprocess"` for the project and `runtime = "herdr"` for research only.

## When an agent ends

Both runtimes give each agent a `PILOOP_WORKER_TOKEN` of its own, and every process that the agent starts inherits
it, also a command that runs in a session of its own, as Claude Code's Bash calls do. When the agent ends (its run is
over, it times out, a stop or a cancel ends it), piloop ends every process that carries its token. A build that forks
meanwhile is stopped first, so none of its children is left.

- A shared server that an agent starts, such as an sccache, Gradle or Bazel daemon, carries the agent's token too, and
  ends with the agent. The next agent that needs it starts it again. Start it outside piloop to keep it running.
- What piloop itself starts is never tagged: the daemon, also one that an agent starts with `piloop serve --detach`,
  and the evaluations.
- A process that clears its environment (`env -i`) loses the token, and piloop cannot find it.

## Add a runtime

A Python package adds a runtime with an entry point in the `piloop.runtimes` group. The class implements the
[`Runtime` protocol](/architecture/extension-points#runtimes). This runtime starts each agent as the `subprocess`
runtime does, at a lower CPU priority:

```python
from dataclasses import replace
from typing import ClassVar

from piloop.harnesses import Invocation
from piloop.runtime import Handle, WorkerSpec
from piloop.runtime.subprocess import SubprocessRuntime


class NiceRuntime(SubprocessRuntime):
    """``nice``: background processes, like ``subprocess``, at a lower CPU priority."""

    kind: ClassVar[str] = 'nice'
    invocation: ClassVar[Invocation] = Invocation.HEADLESS

    def start(self, spec: WorkerSpec) -> Handle:
        return super().start(replace(spec, executable='nice', args=['-n', '10', spec.executable, *spec.args]))
```

```text
[project.entry-points."piloop.runtimes"]
nice = "my_package:NiceRuntime"
```

Install the package in the environment of `piloop`. A project then sets `runtime = "nice"`, or a role sets it in its
own table. `piloop init` refuses a name that no runtime has. A name that a built-in runtime has already, a `kind` that
is not the name of the entry point, or a class without an `invocation` is an error that names the entry point.

`piloop attach`, `piloop prompt`, `piloop doctor` and `piloop watch` call the methods of the runtime, so they work with
the new runtime at once.
