## Variables that you set

These are the settings of the daemon and the CLI. The table comes from piloop's settings.

{/* Generated by scripts/gen_docs.py: settings. Do not edit this part: run `make docs`. */}

| Variable | Default | Meaning |
|---|---|---|
| `PILOOP_HOME` | `~/.piloop` | The directory that holds the database, the artifact store and the directories of each run (worktrees, logs, workspaces). |
| `PILOOP_ACTOR` | `human` | Who this process is. Every row it updates records this value in `updated_by`. The daemon launches each agent with `<role>#<worker_id>`, for example `worker#12` or `scout#7`. |
| `PILOOP_TICK_SECONDS` | `2` | The number of seconds between two ticks. On each tick, the daemon checks the triggers of every project and launches the requested workers. |
| `PILOOP_SECRETS_COMMAND` | none | A shell command that prints `NAME=value` lines: the API keys that the `[mcp.<name>]` servers name, from wherever you keep them. The daemon runs it when it starts and on every `piloop restart`. The keys go into the daemon's environment only, never into a file or a log. When unset, the daemon has only the environment that `piloop serve` started with. |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | none | The standard OTLP endpoint. piloop exports traces only when this is set. |
| `PILOOP_ENTIRE_ATTACH_TIMEOUT_SECONDS` | `120` | The number of seconds that `entire session attach` may take to turn the session of an ended agent into a checkpoint. After that, it is stopped and the checkpoint stays NULL. |
| `UV_TOOL_DIR` | `~/.local/share/uv/tools` | Where uv keeps its tools (uv's own `UV_TOOL_DIR`). The default is uv's default when `XDG_DATA_HOME` is not set. `piloop upgrade` reads the `uv-receipt.toml` of the piloop tool there to learn where the CLI was installed from. |
| `PILOOP_DEBUG` | `false` | Show the full traceback of an unexpected error in the CLI, instead of a short message. |
| `PILOOP_AGENT_SKILLS_DIR` | `~/.agents/skills` | The user directory of Agent Skills, which Codex, pi, Gemini CLI and Cursor read. piloop installs the orchestrator skills there for them. |
| `PILOOP_STORAGE__<KEY>` | [its table](/reference/configuration#storage) | `[storage]` in `config.toml`: where archived workspace files go. |

{/* End of the generated part: settings. */}

### Herdr

These are the settings of the [`herdr` runtime](/concepts/runtimes). The defaults of the timeouts suit most machines.

{/* Generated by scripts/gen_docs.py: herdr-settings. Do not edit this part: run `make docs`. */}

| Variable | Default | Meaning |
|---|---|---|
| `PILOOP_HERDR_SESSION` | `piloop` | The name of the Herdr session that piloop owns. It has one workspace for each project, and every agent that piloop starts runs there, never in the session you use for other work. `piloop attach` attaches a terminal to it. piloop starts its server when it first needs it. |
| `HERDR_SOCKET_PATH` | none | The socket of the Herdr session that this process runs in. Herdr sets it in every pane it manages. `piloop attach` reads it to tell whether it already runs inside the piloop session. |
| `PILOOP_HERDR_SERVER_START_SECONDS` | `10` | The number of seconds to wait for the Herdr server of the piloop session to answer after piloop starts it. |
| `PILOOP_HERDR_START_TIMEOUT_SECONDS` | `60` | The number of seconds Herdr may take to detect an agent that just started. |
| `PILOOP_HERDR_CLI_TIMEOUT_SECONDS` | `30` | The timeout in seconds of one `herdr` CLI call, in addition to any wait that the call itself does. |
| `PILOOP_HERDR_UNAVAILABLE_SECONDS` | `300` | The number of seconds to keep retrying a read of the Herdr server that does not answer (`server_unavailable`, or a `herdr` call that times out) before the read fails. A loaded host can stall the server for a while, and a failed read of a working agent ends it. Calls that change something (a prompt, keys, a new tab) are never retried, because the server may have applied them. |
| `PILOOP_HERDR_PROMPT_PICKUP_SECONDS` | `5` | The number of seconds to wait for an idle agent to start working again after piloop prompts it to resume, and for Herdr to report the session id of a started agent. The first prompt has `startup_grace_seconds`. |
| `PILOOP_HERDR_STARTUP_GRACE_SECONDS` | `60` | The number of seconds an agent has to start its first turn after its brief is submitted. Within it, an agent whose state has not changed yet is still starting, not a lost prompt, and a quiet idle screen is not a finished turn: under load a TUI can take many seconds to show that it took the brief. After it, a brief that was never picked up is lost, and an agent that never worked counts as failed to start. |
| `PILOOP_HERDR_SHELL_READY_SECONDS` | `10` | The number of seconds to retry `agent start` while the shell of a new tab is still starting. |
| `PILOOP_HERDR_WAIT_CHUNK_SECONDS` | `10` | The longest `agent wait` call, in seconds. piloop notices a worker whose tab was closed within this time. |

{/* End of the generated part: herdr-settings. */}

### Other variables

| Variable | Default | Meaning |
|---|---|---|
| `PILOOP_PROJECT_<KEY>` | none | Overrides a key of `piloop.toml` when `piloop init` reads the file. `piloop init` stores the result, and the daemon uses it until the next `piloop init`. Set on `piloop serve`, it has no effect. Join nested keys with `__`, for example `PILOOP_PROJECT_RUNTIME=herdr`. `piloop doctor` reads it too. |
| `CLAUDE_CONFIG_DIR` | `~/.claude` | Claude Code's configuration directory. `piloop install-skills` writes Claude Code's skills to its `skills/` directory. The usage glob of the `claude` harness reads it (`{env:CLAUDE_CONFIG_DIR:~/.claude}`). |
| `CODEX_HOME` | `~/.codex` | Codex's home directory. The usage glob of the `codex` harness reads it (`{env:CODEX_HOME:~/.codex}`). |
| `PILOOP_SRC` | PyPI | For `install.sh` only: install piloop from this checkout or pip-style URL instead of from PyPI. |

A usage glob of a harness can read any variable with `{env:NAME:default}`. `piloop service-unit` carries each one that
the harnesses name.

## Variables that piloop sets

| Variable | Set for | Meaning |
|---|---|---|
| `PILOOP_ACTOR` | every agent | The agent's signature, `<role>#<worker-id>`, for example `worker#12` or `scout#7`. |
| `PILOOP_HOME` | every agent | The same directory as the daemon's, so that the agent's `piloop` commands use the same database. |
| `PILOOP_UNITS_FILE` | the evaluate command, in piloop's own measurements only: the daemon's, and the baseline that `piloop init` measures. Never in an agent's environment. | The path where the evaluate command may write its [per-unit results](/concepts/projects#per-unit-results). |
| `PILOOP_WORKER_TOKEN` | every agent, with the Herdr runtime | A token that lets piloop find the background jobs that an agent started. |
| `CLAUDE_CODE_CHILD_SESSION` | every agent, set to empty | Claude Code sets it for every process that it runs. A Claude Code agent that inherits it saves no transcript, so piloop clears it. |
